# 版型規格與偵測邏輯

## 適用的表格版型

台灣公共工程估驗計價文件常見的一種標準格式：一張表橫向分成幾個欄位群組，
每個群組底下再分「數量」「複價」（原契約群組通常還有「單位」「單價」）。

```
       原契約              前期累計        本期完成        累計至本期
項次 工程項目 單位 數量 單價 複價   數量 複價    數量 複價    數量 複價
壹.一 主體工程費 式  1  ...  ...        ...  ...      ...  ...      ...  ...
```

實務上看過的群組標題文字變體：
- 「原契約」／「原派工」（同一個概念，不同機關或不同期的檔案可能用不同字）
- 通常還有「第一次變更設計(議價前)」這種變更設計群組，本工具目前只讀取但不
  特別核算它

## 自動偵測邏輯（`scripts/verify_payment.py` 的 `SheetLayout`）

1. 掃描前15列，找出「哪一列同時出現最多個群組標題文字」，當作群組標題列。
2. 群組標題列的下一列，是子標題列（單位/數量/單價/複價）。
3. 每個群組的欄位範圍 = 從該群組標題出現的欄開始，到下一個群組標題出現的欄
   為止；範圍內比對子標題列的文字，抓出「數量」「單價」「複價」各自在哪一欄。
4. 項次代碼欄／工程項目名稱欄：在群組標題列往前找文字是「項目」「項次」
   （代碼欄）或「工程項目」「項目名稱」「名稱」（名稱欄）的儲存格。找不到就
   預設代碼欄=A欄、名稱欄=B欄。
5. 資料列範圍：從子標題列下一列開始，往下掃到代碼欄+名稱欄連續8列都是空的
   為止；途中如果某一列的數量/複價欄出現「不是公式的純文字」（例如表尾簽名
   欄的文字誤入資料範圍），或這一列名稱含「總計」，就停止往下掃——總計是
   資料區公認的最後一列，之後接的通常是簽名欄、日期註記等表尾內容。

偵測失敗（找不到任何群組標題）時會丟出 `LayoutError`，訊息會說明原因。遇到
新版型抓不到欄位時，先用下面的方式看它實際抓到什麼：

```python
import openpyxl
from scripts.verify_payment import SheetLayout
wf = openpyxl.load_workbook('檔案.xlsx', data_only=False)['分頁名稱']
print(SheetLayout(wf).describe())
```

### 新增群組同義詞

如果新檔案用了不在 `GROUP_NAMES` 裡的標題文字（例如「原契約」被寫成別的
說法），在 `verify_payment.py` 的 `GROUP_SYNONYMS` 字典裡加一筆對應即可，
不用改偵測邏輯本身：

```python
GROUP_SYNONYMS = {'原派工': '原契約', '新的說法': '前期累計'}
```

## 五種檢查在做什麼

| 檢查 | 需要的欄位 | 邏輯 |
|---|---|---|
| `extended_price` | 單價（本期完成群組或退回原契約群組）、本期完成數量、本期完成複價 | 單價 × 數量 四捨五入 應等於複價 |
| `within_period` | 前期累計複價、本期完成複價、累計至本期複價（數量欄位選填） | 前期 + 本期 = 累計 |
| `subitem_sum` | 任一群組的複價欄 | 偵測 `=SUM(x:y)` 公式的小計列，驗算子項加總 |
| `cross_period` | A檔累計至本期、B檔前期累計 | 用項次代碼配對，代碼是空的（如「總計」列）改用名稱配對 |
| `display_text` | 同 cross_period | 依各自 `number_format` 轉成畫面顯示文字再比對 |

## 為什麼有 display-text 檢查

底層數值比對只回答「數學上算得對不對」，但估驗計價文件是要給人審查、用印、
歸檔的——審查的人看的是螢幕或紙本上顯示出來的文字，不會逐一點開儲存格看
完整精度。兩份不同人員、不同期製作的檔案，儲存格的顯示格式設定（小數位數、
千分位、零值顯示方式）常常不一樣：同一個數字（例如 0.367188），一份顯示成
「0.37」，另一份顯示成「0.367188」，畫面上完全不像同一回事。

`render_excel.py` 的 `render_display()` 把 (數值, number_format) 轉成「Excel
實際會顯示的文字」，`check_display_text_cross()` 拿這個顯示文字去比對，這樣
才能同時抓到「格式不同造成的視覺落差」跟「數字真的不一樣」兩種狀況，並且
分開回報——這兩種問題的處理方式完全不同（前者是統一格式，後者是真的要
修正金額）。

## 已知限制

- 只支援本工具描述的這種「橫向群組」版型；完全不同結構的表格（例如逐列
  單一群組、或用色塊而非文字標題分組）目前抓不到，會丟 `LayoutError`。
- `subitem_sum` 只認得 `=SUM(x:y)` 這種單一連續範圍的公式，不處理
  `=SUM(x:y,z:w)` 這種多段範圍或 `=x+y+z` 這種手動加總公式。
- 百分比費用列（例如「營業稅＝(某幾項複價加總)×5%」）不是單價×數量的標準
  算式，`extended_price` 檢查會因為找不到有效的「單價」而自然跳過這種列，
  不會誤判；但也不會主動幫你驗算這類特殊公式，需要另外人工確認。
