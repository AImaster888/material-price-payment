# 估驗計價核算技能 — 使用手冊（給人看）

**手冊版本 v1.1（2026-09-27／民國 115.09.27）｜對應技能版本 v1.2.0（2026-09-27）**

> 這份手冊給「要審估驗計價、但不會寫程式」的人看。
> 同一個技能有兩份說明：
> - **給電腦看**：`SKILL.md`——告訴 Claude 什麼時候觸發、跑哪個指令、怎麼回報。
> - **給人看**：本手冊——告訴你這個技能在核什麼、怎麼叫它、報告怎麼讀、讀完你還要自己確認什麼。
>
> 兩份的步驟一一對應（見第 8 節）。照本手冊做，就能知道電腦做了什麼、沒做什麼。

---

## 1. 一句話說明

丟兩期估驗計價的 Excel 進來，技能會**逐列**幫你核五件事，把對不起來的列指出來。
數字全部由 Python 程式從 Excel 讀出來計算，**AI 不心算任何數字**，只負責把結果翻成白話。

---

## 2. 它幫你核哪五件事

| # | 核什麼 | 白話 | 為什麼要核 |
|---|---|---|---|
| ① | 單價 × 本期數量 ＝ 複價 | 每一列的乘法對不對 | 公式被改成固定值、或四捨五入方式不同 |
| ② | 前期累計 ＋ 本期完成 ＝ 累計至本期 | 同一份檔案自己加得起來嗎 | 某格被手動打了數字（不是公式） |
| ③ | 前一期「累計至本期」＝ 本期「前期累計」 | 兩期接不接得起來 | 前一期修正了，本期忘了跟著改 |
| ④ | 小計 ＝ 底下子項加總 | 小計的 SUM 範圍有沒有拉錯 | 新增項目後 SUM 範圍沒拉到 |
| ⑤ | 兩期**畫面顯示的文字**一不一樣 | 印出來、螢幕上看起來一不一樣 | 數字一樣但小數位數設定不同，審查時會被質疑 |

①②④ 只要一份檔案就能核；③⑤ 需要前後兩期。

### 它**不**核什麼（要自己看）

- **變更設計群組**（例如「第一次變更設計(議價前)」）：只讀取，不核算。
- **百分比費用列**（營業稅＝某幾項×5%、品管費×1% 等）：不是單價×數量，第①項會自動跳過，**不會幫你驗算百分比**。
- **複雜的 SUM**：`=SUM(A1:A5,A8:A9)` 多段範圍、`=A1+A2+A3` 手動加總，第④項認不得。
- **計價總表通常沒有單價欄**：第①項會被略過，報告會出現 ⚠（見第 5 節）。
- 表格版型完全不同（不是「原契約／前期累計／本期完成／累計至本期」橫向排列）的檔案：跑不動，會直接告訴你。

## 3. 開始前準備

### 3-1 安裝（每台電腦做一次）

在 PowerShell 執行：

```powershell
cd D:\320code\material-price-payment
.\setup.ps1
```

裝完**重新開 Claude Code**。

### 3-2 準備檔案（每次核之前）

1. 兩期的估驗計價 xlsx 放在同一個資料夾，檔名建議帶日期，一眼看得出誰先誰後，例如：
   - `1150301-第一期估驗計價.xlsx`（前一期）
   - `1150401-第二期估驗計價.xlsx`（本期）
2. 確認要核的**分頁名稱**，通常兩張都要核、分開跑：
   - `請款明細表`：逐項明細，有單價，五項都能核。
   - `計價總表`：分類彙總，通常沒有單價，第①項會略過。
3. 兩個檔案**都要先關掉**（Excel 開著的檔案有時讀不到）。
4. 檔案要是 Excel **存過檔**的版本（程式讀的是 Excel 存檔時留下的計算結果）。

## 4. 操作步驟

### 4-1 在 Claude Code 裡用（建議）

直接用口語說，要講清楚三件事：**哪兩個檔、誰是前一期、哪個分頁**。

> 幫我核對估驗計價，前一期是 D:\案件\1150301-第一期估驗計價.xlsx，本期是 D:\案件\1150401-第二期估驗計價.xlsx，分頁用請款明細表。

核完請款明細表，再說一次換成「計價總表」。

會觸發這個技能的說法：「核對估驗計價」「估驗計價核算」「跨期比對」「前期累計比對」「核物調」「複價核算」「請款明細表核對」。

### 4-2 不透過 AI、自己跑指令

```powershell
cd D:\320code\material-price-payment
$env:PYTHONIOENCODING="utf-8"
python -X utf8 scripts\verify_payment.py "前一期.xlsx" "本期.xlsx" --sheet "請款明細表" --md
```

- **順序不能反**：前一期在前、本期在後。反了會全部判錯。
- `--md` 會在前一期檔案旁邊產生 `前一期檔名-分頁名稱-核算報告.md`，例如
  `1150301-第一期估驗計價-請款明細表-核算報告.md`。兩張分頁各跑一次就有兩份報告，不會互相覆蓋。

## 5. 報告怎麼讀（範例演練）

> 以下範例的案名、金額**已去識別化，數字為示意**；異常的型態與位置照真實兩期檔案實跑的結果。

### 5-1 先看「版型偵測」——這段沒過，後面全部不能信

```
偵測到的欄位版型：
  項次欄=1, 名稱欄=2, 群組標題列=4, 子標題列=5, 資料列=6~161
  【原契約】 {'單位': 3, '數量': 4, '單價': 5, '複價': 6}
  【前期累計】 {'數量': 10, '複價': 11}
  【本期完成】 {'數量': 12, '複價': 13}
  【累計至本期】 {'數量': 14, '複價': 15}
  掃描停止原因：第 162 列起連續 8 列空白
```

你要自己確認兩件事：

| 看哪裡 | 怎麼確認 | 不對的話 |
|---|---|---|
| `資料列=6~161` | 打開 Excel，看表格最後一列（通常是「總計」）是不是第 161 列 | 比 161 還多 → 掃描提早停了，**結果不完整**，不能說全部正確 |
| `{'數量': 10, '複價': 11}` 這些數字 | 是欄位序號：1=A、2=B…10=J、11=K。抽一兩個到 Excel 對一下，J 欄標題是不是「前期累計／數量」 | 對錯欄 → 結果全錯，回報給維護的人 |

### 5-2 再看「核算結果」——每一項一行

```
=== 核算結果 ===
- 單價 x 本期數量 = 複價：共 148 項，異常 0 項
- 前期累計 + 本期完成 = 累計至本期：共 156 項，異常 0 項
- 子項加總反查：共 4 項，異常 0 項
- 跨期銜接比對：共 156 項，異常 2 項
- 畫面顯示文字比對：共 156 項，異常 2 項，其中「格式不同（數字相同）」0 項（統一格式即可）、「數字不同」2 項（金額或數量要修正）

結論：共發現 4 筆異常。
```

異常 0 項＝這項沒問題。有異常的會在下面逐列列出。
「畫面顯示文字比對」那行會直接告訴你：幾項只是格式問題、幾項是數字真的不同。

### 5-3 異常明細怎麼讀

程式印出來的是 `{'欄位': 值}` 格式，看得懂這幾個名字就夠了：

| 名字 | 意思 |
|---|---|
| `a_` 開頭 | 前一期的值 |
| `b_` 開頭 | 本期的值 |
| `qty` | 數量 |
| `amt` | 複價（金額） |
| `_ok: False` | 這一欄對不起來 |
| `disp` | 畫面顯示的文字 |
| `exp_` | 照算式「應該是」多少 |
| `tot_` | 檔案裡「實際寫」多少 |
| `cause` | 畫面顯示不一致的原因：「格式不同（數字相同）」或「數字不同」 |
| `row` | Excel 的第幾列，可以直接到那一列去看 |

用 `--md` 產生的報告會直接整理成表格，比較好讀。

## 6. 四種典型異常，各自怎麼處理

這兩期實跑，四種典型狀況全部出現了，剛好當教材。

### 狀況 A：跨期金額接不起來（前一期改了，本期沒跟著改）

```
跨期銜接比對：異常
  物價調整金額  前一期累計 120,000  ≠  本期前期累計 120,300
  總計          前一期累計 5,000,000 ≠ 本期前期累計 5,000,300
```

- **判讀**：差額一樣（300），「總計」異常是被「物價調整金額」帶出來的，**根本原因只有一個**。
- **處理**：前一期物調金額已經修正，本期的「前期累計」還是舊數字。請款明細表、計價總表**兩張都要改**。
- **你要自己確認**：前一期的新數字才是對的（例如有沒有核定公文）。

### 狀況 B：同一份檔案自己加不起來（固定值誤植）

```
前期累計 + 本期完成 = 累計至本期：異常 1 項
  壹.二 雜項工程費  exp_qty 0.3（應該是）  tot_qty 30（實際寫）
                    金額 qty_ok False / amt_ok True
```

- **判讀**：金額對、數量錯，而且 30 跟 0.3 差太多，不像捨入誤差 → 很可能是**有人在公式格打了固定數字**。
- **處理**：到 Excel 點那一格，看資料編輯列是不是公式。是固定值就改回公式（例如 `=前期數量格+本期數量格`）。
- 這一格錯了，**跨期比對跟顯示比對也會跟著報錯**（同一個原因，不是三個問題）。

### 狀況 C：數字一樣，畫面長得不一樣（格式問題）

```
畫面顯示文字比對：共 15 項，異常 10 項，其中「格式不同（數字相同）」7 項、「數字不同」3 項
  壹.一 主體工程費  cause=格式不同（數字相同）  前一期顯示 0.37     本期顯示 0.367188
  壹    發包工程費  cause=格式不同（數字相同）  前一期顯示 -        本期顯示 0.00000
  壹.二 雜項工程費  cause=數字不同              前一期顯示 30   本期顯示 0.3
```

- **判讀**：看 `cause` 就好，程式已經比對過底層數值。
  - 「格式不同（數字相同）」：數字沒錯，只是小數位數設定不一樣。
  - 「數字不同」：數字真的不一樣，回頭看狀況 A、B 找原因（上例的 30 就是狀況 B）。
- **處理**：格式問題不用改數字，把兩期同一欄的「儲存格格式 → 小數位數」設成一樣。不改的話，審查的人對照兩期紙本會以為數字不一致。
- **想自己確認**：點那一格看資料編輯列的完整數值，兩期一樣就是格式問題。

### 狀況 D：出現 ⚠「略過未檢查」

```
- 單價 x 本期數量 = 複價：⚠ 略過未檢查 — 缺少必要欄位（單價/數量/複價）
⚠ 但有 1 項檢查因為欄位不齊沒跑到，不能回報「全部相符」。
```

- **判讀**：計價總表沒有單價欄，這一項**根本沒核**，不是核過沒問題。
- **處理**：計價總表的乘法改成人工抽查，或以請款明細表的核算結果為準。

## 7. 讀完報告，你自己要做的檢核清單

AI 會把結果翻成白話，但**簽名的是你**。每次核完照這張表勾：

- [ ] 前一期／本期檔案**順序正確**（報告開頭的「前一期檔案」確實是較早那期）
- [ ] 兩個分頁（請款明細表、計價總表）**都核過**
- [ ] 版型偵測的「資料列=X~Y」，Y 等於 Excel 裡表格的最後一列
- [ ] 報告**沒有 ⚠**；有 ⚠ 的項目已改用人工核
- [ ] 每一筆異常都有歸類：真的錯（要改金額）／固定值誤植（改回公式）／只是格式（統一格式，看 `cause`）
- [ ] 多筆異常若差額相同，已找出**共同的根本原因**，沒有重複處理
- [ ] 百分比費用列（營業稅、品管費、利潤、保險）已人工驗算
- [ ] 修正完 Excel **存檔後重跑一次**，結論是「全數正確」（exit code 0）

> **只有重跑後完全沒有異常、也沒有 ⚠，才能說「這兩期估驗計價核算全數正確」。**

## 9. 常見問題

**Q：出現「找不到分頁」？**
分頁名稱要一字不差，報告會列出這個檔案實際有哪些分頁，照抄即可。

**Q：出現「版型偵測失敗」？**
表格標題可能用了沒見過的寫法（例如把「原契約」寫成別的詞）。把錯誤訊息原樣給維護的人，照 `docs\FORMATS.md` 加同義詞，**不要手動抄數字應急**。

**Q：金額差 1 元要不要管？**
程式容錯是複價差 < 0.5 元才算相符，差 1 元一定會報出來。捨入方式已採 Excel 的四捨五入（不是銀行家捨入），報出來的差額是真的差額。

**Q：可以把核算報告寄給別人或上傳嗎？**
報告含真實案件數字，repo 已設定不上傳（`.gitignore` 擋掉 `*核算報告*`、`*比對表*`、`*.xlsx`）。對外寄送依機關規定處理。
