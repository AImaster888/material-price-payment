台灣公共工程「估驗計價」文件逐項核算工具。給 Claude Code 用的 skill，也可以
單獨當 CLI 腳本用。

## 這個工具在解決什麼問題

估驗計價文件審查最容易出錯、也最容易被人工審查漏掉的幾件事：

1. **單價 × 本期數量 是否等於複價**——每一項逐列核對，不是只看小計。
2. **前期累計 + 本期完成 是否等於累計至本期**——同一份文件內部要自洽。
3. **前一期的「累計至本期」，是否等於本期的「前期累計」**——兩期文件的銜接
   數字，理論上一定要一樣，實務上常常因為忘記同步而對不起來。
4. **小計列的複價，是否等於底下所有子項複價的加總**——公式範圍拉錯很常見。
5. **兩份文件同一個數字，畫面上顯示出來是不是長得一樣**——這是最容易被忽略、
   但實際審查時最有感的一項：兩份不同人員製作的檔案，儲存格顯示格式（小數
   位數等）常常不一樣，即使底層數值數學上相等，畫面顯示出來可能完全不像
   同一回事，審查時會被質疑。詳見 [`docs/FORMATS.md`](docs/FORMATS.md)。

所有數字都是 Python 腳本用 openpyxl 讀出、算出來的，AI 只負責讀輸出、翻譯成
人話——不會有「AI 口算覆核」把錯的東西講成對的風險。

## 安裝（Claude Code）

```powershell
git clone <this-repo-url> D:\320code\material-price-payment
cd D:\320code\material-price-payment
.\setup.ps1
```

重啟 Claude Code，說「核對估驗計價」「跨期比對」之類的話就會觸發。

## 直接當 CLI 用

```bash
pip install -r requirements.txt

# 只核一份檔案（單價x數量、前期+本期=累計、子項加總反查）
python scripts/verify_payment.py 本期估驗計價.xlsx --sheet 請款明細表

# 兩份檔案一起核（上面三項兩期各核一次，再加上跨期銜接比對、畫面顯示文字比對），並輸出 md 報告
# 順序一定是「前一期在前、本期在後」
python scripts/verify_payment.py 前一期.xlsx 本期.xlsx --sheet 請款明細表 --md
```

`--sheet` 換成你要核的分頁名稱即可，欄位版型是自動偵測的（見下方「適用範圍」）。

## 適用範圍

適用於「橫向分成原契約／前期累計／本期完成／累計至本期幾個欄位群組」這種
台灣公共工程常見的估驗計價表格式。欄位的字母位置是自動偵測的（用標題文字
搜尋，不是寫死的欄位字母），所以不同機關、不同案子的範本大多可以直接用；
真的抓不到版型時，工具會清楚說明抓到什麼、缺什麼，方便手動排查或擴充。
細節見 [`docs/FORMATS.md`](docs/FORMATS.md)。

## 開發

改動核算邏輯前後都要跑：

```bash
python tests/run_tests.py
```

測試用的是合成假資料，不含任何真實案件內容。專案規則見 [`CLAUDE.md`](CLAUDE.md)。

exit code：`0`=已跑的檢查全數相符、`1`=有異常、`2`=有檢查因欄位不齊被略過
（不可當成全部相符）、`3`=檔案/分頁/版型有問題，根本沒跑成。

## 版本歷程

### v1.3.0（2026-09-27）

- 修正畫面顯示比對誤報：空白格原本被當成 0 依格式渲染（例如兩期都空白，卻報「0.00 vs
  0.000000」）；現在空白格顯示為空，且「空白」與「-」（0 用會計格式顯示）視為一致。
- 新增 `examples/` 兩期練習用假資料範例檔（埋了四種典型錯誤，可當安裝驗收）與產生腳本。
- 新增 `docs/快速上手.html`：給一般同仁的一頁式步驟手冊，附 Excel 實際畫面截圖
  （`docs/img/`，由範例檔自動產生）。原 `docs/使用手冊.md` 改名為 `docs/詳細說明.md`。
- 兩期一起核時，「單價x數量」「前期+本期=累計」「子項加總反查」改為前一期、本期**各核一次**
  （原本只核前一期，本期自己的錯會漏掉），輸出標題分別帶「（前一期）」「（本期）」。

### v1.2.0（2026-09-27）

- 畫面顯示文字比對的每一筆異常加上 `cause`：「格式不同（數字相同）」或「數字不同」，
  摘要行與 md 報告都印出兩類各幾項。原本要讀報告的人自己去對照跨期比對推斷，最容易講錯。
- `--md` 報告檔名加上分頁名稱（`<前一期檔名>-<分頁名稱>-核算報告.md`），先核請款明細表
  再核計價總表不會再互相覆蓋。
- `SKILL.md` 路徑說明句改寫，`setup.ps1` 安裝時不再把說明文字裡的佔位符也換成實際路徑。
- 新增給人看的使用手冊（v1.3.0 起改名為 `docs/詳細說明.md`）。

### v1.1.0（2026-08-25）

修掉一批「會靜默漏檢」與「會誤報」的問題：

- 資料列掃描拿掉 400 列硬上限，並把**掃描停止原因**印在版型描述裡，不再靜默截斷。
- 「本頁總計」「承前頁總計」這類分頁彙總列不再被誤當成資料區結尾。
- 檢查因欄位不齊被略過時，exit code 改為 `2` 並印出 ⚠，不會再跟「全部相符」同碼；
  檔案/分頁/版型問題改為 `3` 並印出人話訊息（含該檔實際有哪些分頁），不再吐 traceback。
- 複價四捨五入改用 Excel `ROUND` 的規則（原本用 Python `round()` 的銀行家捨入，
  單價帶小數時會憑空生出假異常）。
- 三個複價欄都空白的大項標題列，不再被誤判為「累計欄漏填」。
- 跨期配對的項次代碼／名稱會先正規化（數字 `1` 與文字 `"1"`、全形空格、縮排都不再影響配對）；
  本期出現重複項次時判為「無法配對」而不是亂配。
- 跨期比對加上反向掃描：前一期沒有、但本期「前期累計」有金額的項目也會被抓出來。
- `子項加總反查` 認得 `$` 絕對位址與小寫 `sum`，並依公式實際引用的欄位加總。
- `--md` 產出的核算報告納入 `.gitignore`（原本只擋 `.xlsx`，`.md` 會被誤上傳）。

### v1.0.0（2026-08-25）

首版：五種核算檢查、欄位版型自動偵測、Claude Code skill 封裝。
